## Limits and repeat checks

This is a point-in-time SQL audit, not a live-production guarantee or a content,
credential, storage-object or full model-validation audit. SQL btrim removes
ordinary spaces by default; repeat normalization/collision checks using the exact
Ruby concern semantics before any data backfill. No objects were fetched from
Spaces, and no destructive data repair was performed.

Before deployment, repeat these aggregate checks against a fresh local snapshot
or through an explicitly read-only production audit. For each proposed FK, use a
LEFT JOIN to its target and count missing target IDs. For uniqueness, GROUP BY
the actual indexed expression/columns with HAVING count(*) > 1; include null
role scopes and the final text normalization policy. Count missing/blank required
identities and invalid ordering values independently. Inspect any violations
privately and obtain an explicit repair decision rather than deleting/renaming
records automatically. Rehearse migrations on a disposable restored copy, not
on the preserved audit snapshot or the working development/test database.

## Installed Devise behavior

Inspected installed Devise 5.0.4 `lib/devise/models/validatable.rb` and this
application's Devise initializer, rather than assuming current defaults:

- Email presence when email_required? (true by default).
- Email uniqueness, case_sensitive: true, allow_blank: true, when email changes.
- Email format against email_regexp, allow_blank: true, when email changes.
- Password presence and confirmation when the record is new or password or
  password_confirmation is supplied (not nil).
- Password length with the configured minimum/maximum, allow_blank: true.
  This application configures 6..128.

Devise's configured case_insensitive_keys and strip_whitespace_keys both include
email. The explicit User presence/format checks duplicate :validatable, while its
case-insensitive uniqueness check expresses a stronger rule worth retaining.
The plan preserves Devise password/recovery semantics and backs email identity
with a unique lower(email) database index.
